# 滚轮缩放为什么自己做，而不用 MapLibre 自带的

这份文档只记一件事：地图滚轮缩放那段代码（`web/map.js` 里的 `wireWheelZoom`）为什么不是直接调用 MapLibre 的能力。以后要重写地图交互时，先看这里再决定。

## 结论先说

自带的能用，我们不用它，是为了控制节奏，不是为了数学。数学上两边做的是同一件事：缩放前后，鼠标下面那个世界坐标不动。哪天真要简化代码，换成自带的是合理选择。

## MapLibre 自带的两种用法

- **默认滚轮缩放**：不写任何代码，`ScrollZoomHandler` 就是按鼠标位置缩放的，一次滚轮滚一格，动画自己跑。
- **手动跳转**：`map.jumpTo({ zoom, around: point })` 或 `map.easeTo({ zoom, around })`，`around` 就是要保持不动的那个点。

两种都是成熟实现，没有坑。

## 我们自己写的原因

1. **按帧推进，一帧只写一次相机。** 现在的实现是一个 `requestAnimationFrame` 循环，攒到目标级别后每帧走一小步。滚轮一次只加一小步，触控板一次可能来几十个事件；如果每个事件都走 MapLibre 的 `jumpTo`，同一帧里相机会被写多次，`moveend`、`zoom` 这些事件跟着来一串。
2. **要限制单次最多放大几级。** 触控板两指猛推一下，自带的会直接跳很多级，画面上的影像来不及按新视野重采样，看着就是白一下再出来。我们按 `dz = clamp(-dy / 500, ±0.6)` 卡住每一步。
3. **和取数、贴图刷新对齐。** 这个软件里，栅格是一张贴图，矢量是按视野向引擎要的。缩放过程中要暂停贴图刷新，停稳之后才去要新的一屏。自己有循环，就能在同一个地方决定"这一帧不动作"。
4. **手感统一。** 鼠标滚轮和触控板走同一套步长，不会一个快一个慢。

## 代价

数学得自己算，而且很容易算错。我们第一版是这么补的：先把鼠标位置对应的经纬度记下来，缩放之后再算一次偏差，把偏差加到地图中心上。看着像对的，其实不对，因为墨卡托投影在纵向不是线性的，缩放一级多一点，误差就攒成九个多像素，肉眼就是"放大的中心不在鼠标上"。

现在的做法换到屏幕像素空间：

```text
缩放前鼠标位置的世界坐标 -> 投影成像素 after
地图中心 -> 投影成像素 cPx
新的中心像素 = cPx + (after - anchorPx)
再反投影回经纬度
```

同一动作实测漂移 0 像素，和 MapLibre 的 `around` 是同一个算法。

## 什么时候该换回自带的

- 地图交互要整体重写，不再需要"每帧一写"的节奏控制。
- 或者发现我们的循环和 MapLibre 自己的相机动画打架，比如同时用了 `flyTo`、`easeTo` 和滚轮。

换的时候删掉 `wireWheelZoom`，打开 `ScrollZoomHandler` 就行，`refreshRaster` 的防抖逻辑不用动，它挂在 `moveend` 上。
