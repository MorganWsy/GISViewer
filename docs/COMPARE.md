# 两份文件对比

顶栏那枚「两份文件对比」按钮打开的浮层，用来比同一份数据的两个版本，或者同一条数据存成的两种格式。整个功能只读：两侧文件一个字节都不改，也不会在磁盘上留临时文件。

## 比什么

**矢量**分三段：

1. 表头与元信息，11 项：文件大小、修改时间、格式、图层数、图层名、几何类型、要素个数、顶点总数、字段个数、范围、坐标系。范围按各自文件的坐标系给，值写成 `(minX, minY, maxX, maxY)`。
2. 字段结构：只在左边有的字段、只在右边有的字段、同名但类型或宽度变了的字段，以及两边的字段顺序是否一致。
3. 属性内容：前 20 行，逐格对照，最多列 300 处差异。

**影像**比尺寸、波段数、数据类型、像元大小、范围、坐标系、NoData、压缩方式、金字塔级数，以及各波段的统计量。影像没有属性表，所以不列第三段。

## 不做什么

属性内容默认**按行号对齐**，不看主键：第 1 行对第 1 行，第 2 行对第 2 行。如果两份文件的要素顺序不同，哪怕内容一样也会报出一片差异。

这是默认行为，不是唯一做法。浮层里那枚下拉可以在两边共有的字段里挑一个，这时改成按该字段的值配对：同一个值算同一个要素，只在一侧出现的值单独计数（"另有 N 个要素只在一边"）。这对应 ArcGIS Pro `Feature Compare` 的 Sort Field，只是做成可选项：不给字段就按行号，给了就按字段。

为什么默认不配对：配对要先选一个能唯一标识要素的字段，还要处理重名、空值、类型不一致。这些是数据质检的判断，不该由"看一眼"的功能替用户拍板。

成熟的同类做法也分这两层：

- ArcGIS Pro 的 `Feature Compare` 必须指定一个 Sort Field（两边共有、能唯一标识要素的字段），再逐要素比几何与属性；不指定就无法配对。它还有 `Continue Comparison` 选项，默认比到第一处差异就停。
- QGIS 原生的 `Detect dataset changes` 产出 unchanged / added / deleted 三类，同样依赖要素身份。
- QGIS 插件里 `Table Compare` 比字段级内容、`Table Structure Compare` 比字段名类型长度、`FeatureClassCompare` 比要素数、几何类型、字段定义与几何指纹，这几个是"结构 + 抽样"路线，与本功能同档。

## 边界与代价

- 顶点总数与属性抽样是同一次遍历里取的，单侧重扫有时间与条数上限（8 秒 / 20 万要素），超了会在结果里标成部分统计，不阻塞整张对照表。
- 两侧必须是同一类。矢量对影像会直接拒绝，并说明左边是什么、右边是什么。
- 图层默认都取第 0 层；多图层文件的其余图层目前不在界面上切换，接口上留了 `layer_a` / `layer_b`。
